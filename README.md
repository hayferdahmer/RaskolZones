## Статус проекта

**Статус: разработка — foundation, Territory Core, Spatial Query Engine, Territory Transition Engine, Rule Resolution Engine, Rule Registry / Evaluation Pipeline и первая итерация Rule Profiles / Inheritance Engine**

Реализованы bootstrap плагина, строгая конфигурация, health/lifecycle, асинхронное SQLite-хранилище, World Registry, Territory Core и первая итерация Spatial Query Engine: immutable snapshots по UUID мира, пространственная сетка 128 блоков, overflow для крупных территорий и точная проверка геометрии. Первая итерация Territory Transition Engine отслеживает вход/выход, проход через узкие области, телепортации и смену миров. Первая итерация Rule Resolution Engine реализует матрицу A-37/A-38, fail-closed для неизвестных источников и decision trace. Добавлены SQLite Rule Registry (schema v4) и Rule Profiles (schema v5) и асинхронный Evaluation Pipeline, связывающий spatial query, активные правила территории и resolver. Добавлены типовые профили правил и наследование по цепочке предков; индивидуальное правило территории подавляет профиль её типа на том же action key. Реализована базовая типизированная модель контекста и детерминированный evaluator условий (актор, цель, тип цели, событие, мир, диапазон Y); условия пока не хранятся в БД и не привязаны к отдельным определениям правил. Receipts A-39/A-40, Paper enforcement listeners для PvP/PvE/build/interactions, команды и редактор ещё не готовы. Зафиксированные в документации требования описывают целевую систему, а не уже реализованные функции.

CI включает Maven-тесты, инспекцию JAR и запуск на Paper 26.2 с проверкой готовности плагина, инициализации пространственных индексов и миграций SQLite до схемы v3.

## Назначение

Плагин предназначен для создания и управления географией игрового мира: территориями и их иерархией, геометрическими границами, правилами доступа и поведения, исследованием мира, атласом и внутриигровым редактором. Внешние системы подключаются через необязательные адаптеры.

## Целевая платформа

- Paper 26.2
- Java 25
- Обычный серверный Paper-плагин
- Клиентские модификации не требуются

Core должен работать без Towny, BlueMap, WorldEdit, WorldGuard и LuckPerms. Эти интеграции являются необязательными.

## Архитектурные принципы

- Собственная географическая модель и движок территорий.
- Безопасное разрешение пересечений и прав; неопределённое разрешение не открывает доступ.
- Разделение доменной логики, хранения и адаптеров.
- Защита целостности данных, аудит административных операций и контролируемое восстановление.
- Измеряемые критерии производительности, тестирования и выпуска.

## Текущие ограничения

World Registry фиксирует UUID миров, отображаемые имена, время первого/последнего обнаружения и состояние загрузки. Territory Core сохраняет территории и базовую геометрию, проверяет родительские связи и конкурентные изменения. Обработка перемещений и переходов игроков реализована первой итерацией: Paper-listener передаёт координаты в тестируемый движок, который публикует TerritoryTransitionEvent. Кэширование результатов запросов, команды, редактор и прикладные игровые правила ещё не реализованы.

Проект разрабатывается на Java 25 / Paper 26.2 с Maven. Компиляция и unit-тесты дополняются runtime smoke test на целевом Paper; успешная проверка одного слоя не заменяет остальные. Первый Alpha появится после прохождения критериев из [дорожной карты](docs/ROADMAP.md).
