# Разработка RaskolZones

## Требования

- JDK 25.
- Maven 3.9+.
- Paper 26.2 для runtime smoke test.

## Сборка и unit-тесты

Из корня репозитория:

```bash
mvn --batch-mode --no-transfer-progress clean verify
```

Готовый JAR находится в `target/raskol-zones-0.1.0-SNAPSHOT.jar`.

Paper API подключается с областью `provided`: API предоставляет сервер. SQLite JDBC включается в JAR плагина, поскольку сервер не обязан предоставлять этот драйвер.

## Конфигурация, хранилище и состояние runtime

- Конфигурация проверяется строго: `language` должен быть корректным языковым тегом, `diagnostics.enabled` — boolean.
- Некорректные типы и языковые теги приводят к ошибке загрузки, а не к незаметной подстановке значений по умолчанию.
- Runtime публикует новый неизменяемый снимок настроек только после успешной загрузки.
- SQLite инициализируется асинхронно на выделенном executor. Основной поток Paper не ожидает открытия базы или выполнения миграций.
- Состояние `READY` выставляется только после успешной инициализации конфигурации и SQLite, а также завершения обязательной начальной регистрации уже загруженных миров. Ошибка любого обязательного шага переводит health в `FAILED`, после чего плагин отключается.
- База `plugins/RaskolZones/raskolzones.db` использует WAL, foreign keys, busy timeout и версионируемые миграции.
- Транзакции выполняются последовательно на выделенном потоке SQLite; обработчики Bukkit не должны блокировать основной поток ожиданием их результата.
- При неудачной перезагрузке конфигурации предыдущий снимок настроек сохраняется, а health переходит в `DEGRADED`. После успешной повторной загрузки состояние возвращается в `READY`.
- При выключении runtime инициирует асинхронное закрытие хранилища; основной поток Paper не ждёт завершения SQLite executor.

World Registry хранит UUID, имя, первое/последнее обнаружение и `LOADED` / `UNLOADED`. При запуске регистрируются уже загруженные миры; `WorldLoadEvent` и `WorldUnloadEvent` обновляют записи без удаления данных. Схема v2 добавляет `world_registry`. Все запросы выполняются асинхронно через storage-интерфейс.

Внутренний вызов `FoundationRuntime.reload()` выполняет перезагрузку через конфигурационный провайдер. Административная команда будет добавлена отдельным этапом вместе с permission-контрактом.

## Paper runtime smoke test

CI автоматически:
1. Собирает плагин на Java 25.
2. Проверяет содержимое JAR и наличие SQLite JDBC.
3. Загружает актуальную стабильную сборку Paper 26.2 и проверяет SHA-256.
4. Запускает сервер с плагином, проверяет состояние `READY`, конфигурацию и создание SQLite-файла.
5. Проверяет миграцию SQLite до версии 2 и наличие записей загруженных миров в `world_registry`.
6. Завершает процесс сервера с ограниченным временем ожидания.

Maven verify и Paper runtime smoke test выполняют разные проверки; оба уровня обязательны.
